# 『外道不覚悟』保存・認証システム設計要件 v1.0

- 制定日: 2026-11-08
- 対象: システム001 / Web版（将来のSwitch等への移植可能性は維持）
- 文書区分: **確定設計要件**。実装方法の選択・数値は「推奨／未確定」と明示する。
- 実装状況: **未実装**。現行フィールド移動v0.4.1のゲームコアには変更を加えない。
- 更新規則: 要件を変更するときは本文の改訂履歴・変更理由・影響範囲を記し、旧版を追跡可能にする。

## A. 基本原則（確定）

| ID | 要件 |
|---|---|
| SAVE-001 | ゲーム開始に実名・Googleアカウント・メールアドレスを必須としない。 |
| SAVE-002 | **ローカル専用／ゲストクラウド／任意のアカウント連携**の3モードを設ける。いずれも基本のゲーム体験をできる限り共通にする。 |
| SAVE-003 | 保存先と認証方式はプレイヤーが選択する。明示操作なしにローカル専用からクラウド保存へ切り替えない。 |
| SAVE-004 | 状態データは自動保存し、再起動後に続きから再開可能にする。保存失敗を隠さずユーザーに示す。 |
| SAVE-005 | 端末間の引継ぎと、将来の保存方式変更時にセーブデータを失わない仕組みを提供する。 |
| SAVE-006 | プレイヤー識別に**IPアドレス、ユーザーエージェントや端末指紋の組合せ**を使わない。 |
| SAVE-007 | プレイヤーデータの削除・書き出し機能を設ける。 |
| SAVE-008 | 移動・戦闘・イベント等のゲームコアは認証SDK・DOM・通信実装に依存させない。DIと共通契約を維持する。 |
| SAVE-009 | 追加機能の実装時に既存の移動・当たり判定・アクション仕様や無関係ファイルを勝手に変更しない。 |

## B. 3つのプレイ・保存モード（確定）

### B1. ローカル専用
- アカウント登録・Firebase認証・ゲームデータのクラウド送信は行わない。
- 同一ブラウザの端末内に自動保存する。
- データ消去・ブラウザ変更・端末故障で失われる可能性を明示する。
- ユーザーが任意でバックアップファイルを書き出し、別端末へ読み込めるようにする。
- 開始時はこれをプライバシー重視の初期選択肢とする。クラウド開始には明示的な選択が必要。

### B2. ゲストクラウド
- Googleログイン・メール登録不要。Firebase匿名認証等による内部ユーザーIDでクラウド保存する。
- 同じブラウザでは認証情報が維持される間、継続利用できる。
- ブラウザデータや認証情報の消去で回復できなくなる可能性を明示する。
- 端末引継ぎには安全な引継ぎ機構か後述のアカウント連携を使用する。IP一致のみで復旧させない。
- クラウド保存・認証に関する最低限の説明を開始前に表示する。

### B3. アカウント連携
- Google認証を選択可能にする。
- Googleアカウント連携に抵抗がある人向けに、メールリンク認証等の代替手段を検討・実装する。
- 同じプレイヤーIDとセーブに複数端末からアクセスできる。
- ゲストからアカウント連携へ移行しても、既存データを保持する。再認証時に別のプレイヤーを誤作成しない。

## C. 識別とプライバシー（確定）

| ID | 要件 |
|---|---|
| ID-001 | プレイヤーIDは認証基盤で発行する不透明ID等で管理し、IPに紐づけない。 |
| ID-002 | 端末IDが必要な場合はブラウザごとにランダム生成し、セキュリティ認証の代替に使わない。 |
| ID-003 | 端末のOS・ブラウザ・画面サイズ等は動作上の必要性に応じた最小限だけ扱い、診断目的で収集するときは目的・送信先を明示する。 |
| ID-004 | クライアントからIPを取得してプレイヤーIDを生成する仕組みを実装しない。ホスティング／認証／通信事業者が接続情報をログ処理する可能性は別途告知する。 |
| ID-005 | 原則としてクラウド保存を選ばないユーザーのゲーム進行をクラウドへ送信しない。 |
| ID-006 | 公開リポジトリ／GitHub Pagesに管理者資格情報・秘密鍵・サービスアカウント鍵を配置しない。 |

## D. セーブ・同期（確定）

| ID | 要件 |
|---|---|
| SYNC-001 | 位置、マップ、プレイヤー状態、進行フラグ等を拡張可能なデータモデルで管理する。 |
| SYNC-002 | データには `schemaVersion`, `slotId`, 更新世代／リビジョン等を設ける。読み込み時は形式検証する。 |
| SYNC-003 | 起動時に保存状態を読み込み、ゲームの初期状態へ安全に反映する。 |
| SYNC-004 | 自動保存は変更検出と間引きを行い、毎フレームのクラウド書込みを禁止する。重要イベント・中断時に追加保存を試みる。 |
| SYNC-005 | オフライン・保存失敗・未同期を判別して表示する。未同期データがサーバーに保存されたと誤表示しない。 |
| SYNC-006 | 端末間の競合は検出し、古いデータによる黙った上書きを避ける。競合の解決規則は実装前に確定する。 |
| SYNC-007 | モード変更・アカウント連携時は既存データのバックアップ／競合確認を行い、ユーザー確認なしに消失・上書きしない。 |
| SYNC-008 | データ削除の対象（端末内／クラウド）を区別し、クラウド削除は適切な再認証・確認の下で実行する。 |

保存頻度「30秒ごと」等は**推奨例であり未確定**。ゲーム負荷・コスト・離脱時のロスを測って決める。

## E. 引継ぎ方式（確定要件・具体化は後続）

1. **バックアップファイル**：書出しと取込みを提供し、改ざん・形式違い・バージョン違いを検知。取込み前に対象セーブと差分／上書き確認を行う。
2. **アカウント連携**：ゲスト認証の継続性を保ちながらGoogle／メール等へ昇格できるようにする。
3. **短期の引継ぎコード**：サーバーを介した端末間の安全な引継ぎを将来提供する。短期有効・一回限り・試行回数制限・推測耐性・可能なら元端末承認が必須。**6桁数字だけで無期限の復旧権限を与えない**。
4. 元端末・認証情報とも失われたときの復旧可能範囲は事前に明示する。「ログイン不要なのに必ず復旧可能」と保証しない。

## F. セキュリティ（確定）

- クラウドの所有権・読み書き権限を、認証済みユーザーIDとサーバー側の認可ルールで強制する（例：Firestore Security Rules）。
- クライアント内の表示制限だけで他者のセーブを保護した扱いにしない。
- 引継ぎ・ユーザーIDの付替え・削除などの特権処理は、必要なら認証付きサーバー処理で行う。
- 保存サイズ・頻度・データ形式を検証し、過剰アクセス・不正書込み・費用急増に対策する。
- ゲームのセーブデータは原則として個人の識別情報、メールアドレス、IPと混ぜない。

## G. アーキテクチャ上の契約（確定）

```text
GameCore (既存の移動・衝突・イベント処理は無改変)
    │ state snapshot / restore
    ▼
SaveManager ── SyncCoordinator
    │                   │
    ▼                   ▼
SaveRepository      IdentityProvider
    ├ LocalRepository    ├ LocalIdentity
    └ CloudRepository    ├ AnonymousIdentity
                         ├ GoogleIdentity
                         └ EmailLinkIdentity
```

- `SaveRepository`・`IdentityProvider`などはインターフェースとして定義し、ブラウザ／Firebase具体実装を外から注入する。
- Firebaseへの接続はアダプタ層に閉じ込め、将来の別バックエンド・ゲーム機移植が可能な境界を維持する。
- 既存コアに直接 `firebase`, `localStorage`, `indexedDB`, `window`, `document` への依存を追加しない。
- AI修正では**許可ファイル・変更目的・変更禁止領域・回帰テスト**を必ず示す。

## H. 現時点の技術候補と開発順序（実装方針・変更可能）

- 第1段階：ローカル自動保存（IndexedDBを第一候補）、起動時復帰、バックアップ書出し／取込み。
- 第2段階：Firebase Authentication匿名認証 + Cloud Firestoreを第一候補としてゲストクラウド対応。
- 第3段階：Google認証とメールリンク認証、匿名アカウントからの連携移行。
- 第4段階：安全な引継ぎコード、複数端末同時プレイ時の競合処理強化。
- GitHub Pagesは静的Web配信、Google Driveは開発成果物の保管、GitHubリポジトリはソース正本。
- 「Firebase」は**現時点の推奨実装候補**であり、利用料金・利用規約・管理方法の最終確認を実装前に行う。

## I. 受入れ基準（検証すべき条件）

1. ローカルモードでログインなしに開始→位置を移動→再読込すると同じ位置に復帰する。
2. ローカルモードでゲーム進行のクラウド保存通信が発生しない。
3. ゲストモードでGoogleログインなしにクラウド保存→同じブラウザで再開できる。
4. ゲストのブラウザ認証を消去してもIP一致だけでは他人のセーブを復元できない。
5. Google／メール連携によって既存ゲストのセーブを消失させず、別端末で再開できる。
6. 他プレイヤーのセーブを未認可で読み書きできない。
7. オフラインで操作してもゲームは継続可能。サーバー未同期ならその旨を表示する。
8. 同時編集で古い保存データによる無言の上書きを防止する。
9. データ書出し・取込み・削除が利用でき、誤上書き前に確認がある。
10. 保存機能の追加前後で、8方向移動、衝突、壁沿いスライド、ダッシュ、XYAB・Z・LR、全画面の回帰テストが通る。
