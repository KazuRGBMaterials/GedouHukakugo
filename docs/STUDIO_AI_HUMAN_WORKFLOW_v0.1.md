# 外道不覚悟 — GEDO STUDIO / AIドラフト→人間最終編集の制作設計（2026-11-08）

## 制作上の原則（確定方針）
**AIが大筋を制作し、最後は開発者が手修正して承認する。**

シナリオ、画像、アニメーション、マップ、音楽、エフェクトのすべてに適用する。
AI出力をゲームの正式設定として黙って取り込んではならない。既存の正史、人物設定、音楽リファレンス、
前チャットからの引継ぎ資料に矛盾するドラフトは、未決事項として明示する。

RPGツクールのように「制作工房」を中央ハブとし、素材はIDで関連付ける。
制作工房がデータの参照・編集履歴を管理するが、各エディターの内部実装を一つの巨大ファイルに統合しない。

## 今回デプロイする最小の縦断構成

| モジュール | 現状 | 共通プロジェクトとの関係 |
|---|---|---|
| ゲーム FIELD v0.8.0 | 実装済み（既存の入力・物理・スキル処理維持） | 操作テスト、グラフィックスキン |
| フィールドエディター | 操作可能 | ローカルマップJSONの手動受渡し |
| 制作工房 /studio/ | **初版実装** | 全分野の記録・編集・参照・承認・JSON入出力 |
| シナリオ | **データ編集の初版** | 場面・台詞・分岐JSON、人物・マップ・音楽とのID参照 |
| キャラクター | **データ編集の初版** | 設定・画像ID・アニメーションID |
| 画像 | **素材台帳の初版** | 画像パス、8方向などの仕様。画像のピクセル直接編集は未実装 |
| アニメーション | **メタデータ編集の初版** | コマ・FPS・ループ・キャラID。タイムラインUIは次段階 |
| 音楽 | **楽曲台帳の初版** | 曲ID、ファイルパス、BPM、ループ点。作曲/音声波形編集は次段階 |
| エフェクト | **演出台帳の初版** | VFX ID、使用スキル、画像ID、アニメID。パラメーター視覚編集は次段階 |

**未実装のことを「できる」と書かないこと。**
現在の制作工房で可能なのは共通レコードを管理し、AI生成ドラフトのJSONを貼って読み込み、
手修正、承認、エディター間のID関連付け、マップの手動受渡しを行うこと。
ブラウザ内からAI APIを自動呼出する機能や、ほかのエディターの完全なUIはまだない。

## 統一データ契約

ローカルキー：`gedo-studio-project-v1`。
エクスポート形式 `gedo-studio/v1`：

```json
{
  "schema": "gedo-studio/v1",
  "version": 1,
  "title": "外道不覚悟",
  "records": {
    "scenes": [], "characters": [], "images": [],
    "animations": [], "maps": [], "music": [], "effects": []
  }
}
```

レコード共通契約：
```json
{
  "id": "asset-uuid",
  "title": "場面の名称",
  "status": "draft",
  "description": "作品内の役割。未確定事項も記録",
  "data": {"chapter": "灼道", "scene": "", "dialogue": []},
  "links": ["asset-other-uuid"],
  "updatedAt": "2026-11-08T00:00:00.000Z"
}
```

- `status` は `draft`（AIドラフト）、`review`（人による手修正中）、`approved`（人が確認し承認）の3段階。
- AIドラフトの貼り付けは `module/title/description/data` を持つJSON（またはその配列）を受け取り、**強制的にdraftで追加する**。AIがstatus=approvedを送っても無視。
- IDは生成ごとに固有値を使い、参照の際はタイトルではなくIDを使用する。
- 手修正を保存するだけでは正式ゲームへのリリースではない。承認済みレコードについても、ゲームに組み込む作業は別の明示的な工程として扱う。
- 過去シナリオ資料との矛盾や素材の不足を承認前に確認する。正史の設定は、人による確認が済むまで更新しない。
- 現版に厳密な権限管理・クラウド共同編集・レコード単位の完全版履歴はない。必要ならGitの変更履歴またはJSONバックアップで残す。

## AIにドラフト制作を依頼する流れ

1. 制作工房で分野を選び「AIへの依頼テンプレートをコピー」。
2. ChatGPTの会話で、対象シーン・キャラ・既存の引継ぎ資料に照らして具体案を検討。
3. ChatGPTがドラフトJSONを作る。例：

```json
{
  "module": "effects",
  "title": "MAGE 炎弾のエフェクト設計案",
  "description": "8方向移動中に使える、金色の魔法陣を使った炎弾",
  "data": {
    "skill": "skill-1",
    "visualId": "",
    "animationId": "",
    "durationMs": 170,
    "notes": "正式演出の長さは手修正で確定"
  }
}
```

4. 制作工房の貼付欄へJSONを貼り「AIドラフトとして追加」。
5. 項目を選び、構造化JSON・説明文を手修正。他のレコードをIDで関連付け。
6. 人間が `approved` に変更する。この時点でようやく採用候補。
7. ゲームへの正式組込・ステージ公開・Gitへのデプロイは、独立した明示的リリース操作で行う（未実装部分あり）。

## 既存FIELD EDITORとの橋渡し

- `docs/editor/` が持つ正本JSONは `schema: "gedo-field-map", version: 1`。
- 同じブラウザのlocalStorageキーは `gedo-field-editor-autosave-v1`。
- 工房の「エディターのマップを工房へ取り込む」は、**コピーしたスナップショットを未承認レコードとして追加**する。エディターの自動保存を書き換えない。
- 工房の「選択中のマップをエディターへ送る」は、明示的な確認ダイアログを出して、対象のローカルマップを差し替える。GitHub/他端末へ公開しない。
- エディターの「本編で試す」は引き続き `?editorMap=1` でローカルプレビュー。通常ゲームは正式マップのまま。
